# 测试索引与修改指南

> 本文件是 `tests/` 的唯一目录索引。**任何新增、删除、改名、合并测试文件，都要在同一次改动里更新本文件**，否则下一次功能变动就找不到该改哪条用例。
>
> 当前：55 个文件、605 条用例（2026-11-24）。

## 一、命名约定

| 层 | 目录 | 命名 | 示例 |
| --- | --- | --- | --- |
| 单元 | `tests/unit/` | `test_<被测模块>_<方面>.py` | `test_file_ops_move.py` |
| 命令行 | `tests/cli/` | `test_cli_<子命令/阶段>.py` | `test_cli_workflow.py` |
| 集成 | `tests/integration/` | `test_<场景>.py` | `test_build_delivery.py` |
| 回归 | `tests/regressions/` | `test_<YYYY_MM_DD>_<主题>.py` | `test_2026_11_23_review.py` |

硬规则：

1. 文件名只描述**被测对象**，不用 `fixes`、`improvements`、`deep`、`regressions`、`misc` 这类无信息词。
2. 同一层内不得重名；**跨层也不要同名 basename**——pytest 默认 `prepend` 导入模式会把同名文件当成同一个模块，直接报 import mismatch（本轮已踩过 `test_cli_entry.py`）。
3. 单元层文件名前缀尽量等于源模块名（`compile_engine`、`file_ops`、`submission`、`ui_theme`），便于按模块反查。
4. 回归层日期用下划线分隔（`2026_11_23`），主题写当时修的那件事，不写轮次编号以外的黑话。
5. 一个文件只放一个主题；主题变大时按“方面”拆（如 `file_ops_move` / `file_ops_same_bytes`），不要堆进 `test_utils.py`。

## 三、功能变动怎么改（增删改查）

### 新增功能

1. **先定位层**：纯逻辑 → `unit/`；新 CLI 阶段 → `cli/`；需要真实子进程/文件交付 → `integration/`；修的是历史故障 → `regressions/`。
2. **新建文件**按第一节命名；若只是给现有模块加一个方面，优先加到同前缀文件，不再新建。
3. **必配断言**：至少一条“行为结果”断言；外部命令要断言完整 argv；负向路径用 `pytest.raises` 或 `pytest.fail`。
4. **CLI 开关**：同时更新 `test_cli_args.py` 的 `FLAG_CASES`、`test_help_mentions_every_public_flag` 的清单；只在 `run_workflow` 新增分派时，补 `test_cli_workflow.py` 的顺序断言。
5. **更新索引**：在第二节加一行；若新增文件，同时更新 `tests/README.md` 的文件数。

### 修改行为

1. 按“被测对象”在第二节查到文件；再按 `-k <函数名>` 定位用例。
2. 改断言前先确认是**契约变了**还是**实现错了**：契约变更要同步改索引里的“关键契约”描述；实现错则修代码而不是放松断言。
3. 断言跨了多层（例如解析 + 真实进程），两层都要补；只改单测会留下“参数被入口丢掉”的空档。
4. 跑 `python -m pytest -q <文件>`，再跑全量；改 CLI 旗标时额外跑 `-m "cli or integration"`。

### 删除功能

1. 删对应用例/文件；若整个文件删掉，第二节删行、`tests/README.md` 改文件数。
2. 同步删 `FLAG_CASES` 行与帮助页清单；保留一条“旧旗标退出 2”的负向用例，防止旧参数被静默接受。
3. 检查 `skip/xfail` 与注释里是否还留着已删功能的说明。
4. 回归层文件保留历史用例，不因功能删除而清空；只把仍在测已删行为的用例移除。

### 查询

- 按模块：文件名前缀 = 源模块名（`test_submission_*` 对应 `submission.py`）。
- 按功能：用第二节“覆盖对象/关键契约”列搜关键词（如“draft”“biber”“退出码”）。
- 按旗标：`test_cli_args.py` 的 `FLAG_CASES` 是唯一事实源。
- 命令：`python -m pytest -q -k "draft or quiet"`。

## 四、运行命令

```powershell
python -m pytest -q                     # 全量 605 条
python -m pytest -q -m "unit or cli"    # 快速反馈
python -m pytest -q -m integration      # 端到端
python -m pytest -q tests/unit/test_compile_engine.py -k stop_reason
```
