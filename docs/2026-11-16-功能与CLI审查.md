## 1. 总体评价（先说做得好的部分）

这套工具已经越过「能编译」的阶段，进入了「编译调度器」的层次，几个设计是同类工具里少见的：



1. **收敛判定有理论依据**：`fixed_point / cycle / stable / log_stalled / limit` 五类停止原因（`compile_report.py:32`），并用 `_convergence_stop_reason` 区分「两态震荡」与「不动点」，比 latexmk 的「固定跑 N 次」稳。

2. **跨进程构建基线**：产物摘要 + 源快照落到共享状态文件，冷启动不必多跑一轮（`build_state.py:104`）；且只在真收敛时写 `converged`，避免把未收敛 PDF 当成品（`compile_engine.py:346`）。

3. **状态文件契约清晰**：单文件多命名空间 + schema v3 + 原子替换 + 尽力锁（`pytexlogs/core/state.py`），PyTeXMK 与 PyTeXLogs 共用而不互相覆盖，这是本项目最值钱的「基础设施」。

4. **中断自愈**：截断 `.aux` 的花括号配平检测（`aux_repair.py`），直接消灭了「每次编译都 `File ended while scanning use of \@writefile`」这类死循环。

5. **日志解析面宽**：11 类工具、`error_pos_text`、行栈还原、`LATEX_LOG_HINTS` 建议表，已经具备「可诊断」的底子，只是上层还没用起来。

6. **工程化到位**：uv + 锁定依赖、`py315` 目标、三平台打包矩阵、`pack/pytexmk` 分发包、两类状态文件、i18n 4 步工作流、Winget/PyPI/install.sh 多渠道。

以下问题基本都是「最后一公里」性质的，修起来收益 / 成本比很高。

## 2. 编译能力：正确性问题（建议最先修）

### C1 增量判定漏掉真实依赖

**现象**：`_iter_tex_sources()` 只 `rglob("*.tex")`（`compile_engine.py:382`），源快照也只用这些文件（`build_state.py:148`）；`_can_skip_compile` 在「上次收敛 + 产物摘要一致 + PDF 存在 + 所有 .tex 未变」时直接跳过（`cli_compile.py:214-220`）。

**后果**（按发生频率排序）：



* 换了一张 `figures/*.pdf / *.png` → 跳过编译，PDF 里还是旧图；

* 改了 `references.bib` → 跳过，参考文献不变；

* 改了自建 `thesis.cls / *.sty` → 跳过，版式不变；

* 改了 `*.bst`、`*.tikz`、`*.asy` 等被 `\input` / 宏包间接读入的依赖 → 跳过（只有 `.tex` 被跟踪，所以 `\input` 进来的章节文件是安全的，其余都不是）。

这是「静默错误」：用户看到的是绿字「源文件与上次编译一致，已跳过编译」，会认为已经更新。

**建议**（两条路径，先快后准）：



1. **快修（半天）**：把依赖快照从「全部 `.tex`」扩成「全部潜在输入」：



```
_DEP_SUFFIXES = {".tex", ".bib", ".bst", ".cls", ".sty", ".def", ".clo", ".cfg",
                 ".ist", ".tikz", ".asy", ".lua", ".py", ".svg",
                 ".pdf", ".png", ".jpg", ".jpeg", ".eps"}
```

图片 / PDF 只需 `(size, mtime_ns)`，不需要哈希；对 `figures/` 这种大目录可用 `st_mtime_ns` 剪枝。



1. **正解（1\~2 天）**：加 `-recorder` 让引擎产出 `.fls`（`SUFFIXES_AUX` 里本来就有 `.fls`，只是从未生成），用 `.fls` 的 `INPUT` 行枚举「这次真正读过的文件」，直接命中 latexmk 的依赖模型；`source_snapshot` 输入改成 `.fls` 解析结果，缺失时回退到方案 1。

顺带：`BuildState.record_fingerprint`、`remove_state_file_if_empty`、`last_stop_reason` 目前没有调用点（`build_state.py:187-218`），可在实现 `--explain` 时一并接上。

### C2 构建状态不含「编译配置指纹」

**现象**：`save_round` 写入 `fingerprint, round, dims, artifacts, converged, stop_reason, signals, sources`（`build_state.py:129-144`），没有引擎、交互模式、`shell-escape`、`draft`、`outdir/auxdir` 的摘要。

**后果**：`xelatex` 编过一次后 `pytexmk -p`（PdfLaTeX）会被判定「源没变」直接跳过；改了 `.pytexmkrc` 的 `compiled_program` 同理。反过来，改动 `quiet_mode` 也会触发一次无意义的重编（因为不影响产物，属于噪声）。

**建议**：加一个 `build_key`：



```
build_key = hashlib.sha256(json.dumps({
    "engine": compiled_program,          # XeLaTeX / PdfLaTeX / LuaLaTeX
    "interaction": non_quiet,
    "shell_escape": shell_escape,
    "draft": draft,
    "outdir": str(Path(outdir).resolve()),
    "auxdir": str(Path(auxdir).resolve()),
    "version": __version__,              # 升级后首次必编，避免旧产物语义变化
}, sort_keys=True).encode()).hexdigest()
```

`_can_skip_compile` 增加 `tracker.build_key_matches(build_key)`；`--explain` 时把差异项打印出来（见 U4）。

### C3 草稿模式改写用户源文件

**现象**：`draft_model` 用正则替换 `\documentclass[...]{...}`，把 `draft` 写回 `main.tex`（`tex_project.py:204-217`）。`RUN` 在成功路径末尾关闭（`compile_engine.py:313`），而失败路径在 `CompileLaTeX.compile_tex` → `_on_subprocess_failure` → `exit_pytexmk` 里直接退出（`compile.py:115-116`），**不会关闭**。

**后果**：



* 编译失败（用户天天遇到）→ `main.tex` 永久带 `draft`，图片全变空框，直到手动删；

* 即便成功，也会造成 git diff 噪声、mtime 变更（进而让下一次的「源快照」永远判定为变过）；

* OneDrive / 杀毒软件占用文件时写回失败，只在 info 级别日志里可见（默认 `WARNING` 阈值下不可见，`logger_config.py:71`）。

**建议**：



* **方案 A（推荐，彻底不碰源文件）**：编译时用 `\PassOptionsToClass` 注入选项。从 `\documentclass` 解析类名后：



```
xelatex -jobname main "\PassOptionsToClass{draft}{ctexbook}\input{main.tex}"
```

（`-jobname` 保持产物名不变；命令行走 `MySubProcess` 的 list 参数，无转义问题）



* **方案 B（改动最小）**：保留改写，但用 `try/finally` 保证关闭，并在写回前做 `.bak`/ 内存备份；同时在状态文件里记录「我曾开启 draft」，下次启动若发现遗留则自动修复（自愈逻辑与 `aux_repair` 同构）。

### C4 bib2gls 从未被调用

**现象**：`bib_judgment` 检测到 `\glsxtr@record` 或 `<bcf:glossary>` 后置 `bib2gls_mode=True`（`detection.py:635-644`），随后快照采集与索引调度都 `continue` 掉 glossaries 规则（`detection.py:535-537`、`723-725`），注释称「它的处理完全由 biber 在同一个 subprocess 里完成」。

**事实**：bib2gls 是独立程序（`bib2gls main`，读 `.aux` + `.bib` 产出 `.glstex/.gls`），biber 不会替你跑。所以 `glossaries-extra` + `\GlsXtrLoadResources` 的项目会得到**空术语表 +&#x20;**`\gls`**&#x20;未定义警告**，而工具会报「编译成功」。

**建议**：按 `biber → bib2gls → xelatex` 的顺序插入一步：



```
if detector.bib2gls_mode:
    cmd = ["bib2gls", "--quiet" if not non_quiet else "--verbose", project_name]
    # 需要 -shell-escape 且 .glstex 生成后再编译一次
```

并把 `latex_compilation_times` 提高 1；同时在 `.gls/.glstex/.glg` 纳入 `TRACKED_ARTIFACTS` 与索引快照。若暂不做，至少把注释改对、并在日志里明确警告「检测到 bib2gls，术语表需手动运行 bib2gls」。

### C5 `-shell-escape` 无条件开启

**现象**：`compile.py:98` 固定 `-shell-escape`。

**后果**：编译一份外来 `.tex`（审稿模板、合作者稿件、arXiv 源码）就等于允许其执行任意命令；同时部分发行版（MiKTeX 默认 `restricted`）行为不一致，反而造成「本机能跑、同事不能跑」。

**建议**：



* 默认 `-no-shell-escape`，配置 `[compile] shell_escape = "auto" | true | false`；

* `auto`：源码里出现 `\usepackage{minted}`、`\usepackage{pythontex}`、`\write18`、`\directlua`、`svg`、`tikzexternalize` 时才开启，并在启动时用一行提示告知；

* 永远在日志里记录本次实际使用的引擎参数（便于复现 issue）。

### C6 PDF 修复会毁掉原文件

**现象**：`pdf_repair` 先 `PdfReader` 读入，然后 `open(pdf_file, "wb")` 就地截断写回（`pdf_tools.py:63-64`）。

**后果**：`writer.write` 中途失败（磁盘满、文件被占用）→ 原 PDF 变 0 字节；即使成功，`add_page` 重建会**丢失书签、大纲、附件、元数据、命名目标**，对学位论文是灾难。

**建议**：



1. 写临时文件 + `os.replace` 原子替换，保留 `.pdf.bak`；

2. 优先 `qpdf --replace-input`（保结构、可修 xref）或 Ghostscript `-dPDFSTOPONERROR`，pypdf 仅作兜底；

3. 只处理 `\includegraphics` 实际引用到的 PDF（可从 `.fls` 取），不要 `rglob("*.pdf")` 全仓扫描；

4. 输出「修复前 / 后大小、页数、书签数」对比，让用户判断是否值得。

## 3. 编译能力：能力缺口（按价值排序）

### 3.1 缺 `watch` / 连续编译

目前每次都要手动敲 `pytexmk`。对「写作 - 编译 - 看图」循环，`latexmk -pvc` 是最刚需的功能。

建议：`pytexmk watch`（或 `--watch`），基于 `watchfiles`（Rust 后端，跨平台、无轮询开销）监听依赖集合（C1 落地后直接用 `.fls` 的文件清单），300 ms 去抖，编译失败不退出循环、只在终端刷新「错误摘要」；`Ctrl+C` 清理一次后退出；与现有的 `_can_skip_compile` 共用判定，避免保存即全量重编。

### 3.2 缺「编译前体检」（pre-flight）

大量失败其实是可在 50 ms 内拦下的：



* 非 UTF-8 / 带 BOM 的主文件（README 明说「仅支持 UTF-8」，`README.md:215`，但没有检查）→ 直接给出「请另存为 UTF-8（无 BOM）」；

* 缺 `\end{document}`（截断文件）→ 报「文件在第 N 行提前结束」而不是让 TeX 抛 40 行日志；

* `\bibliography{}` 指向的 `.bib` 不存在 / `\addbibresource` 路径拼错；

* `\documentclass` 缺失（选错主文件）；

* `\input/\include` 目标不存在（可用 latexdiff 的 flatten 逻辑复用）；

* 图片文件缺失 / 扩展名与 `\includegraphics` 不符（graphicx 的搜索顺序）。

建议做成 `pytexmk doctor`（§U4）的一部分：`doctor` 检查环境，`build` 前跑 `preflight`（默认开，`--no-preflight` 关）。

### 3.3 失败时没有「可执行建议」

`pytexlogs` 已经有 `LATEX_LOG_HINTS / BIBTEX_ERROR_HINTS / BIBER_WARNING_HINTS`，但只有 CSV 导出器用（`exporters/csv_exporter.py:11`）；PyTeXMK 失败时只打印「请查看日志文件」（`subprocess_runner.py:211`）。

建议失败输出改成：



```
✗ XeLaTeX 编译失败（第 1 轮，0.8 s）
  main.tex:132  Undefined control sequence \hl
  提示：缺少 soul 宏包？-> \usepackage{soul}
  日志：Auxiliary/main.log:2048   （--verbose 查看完整解析）
```

`pytexlogs` 的 `LogEntry` 已带 `file/line/error_pos_text`，PyTeXMK 只需把 `print_summary` 的 top-N（见 L4）拿来用，并对「缺宏包 / 缺字体 / 缺文件」三类做 `tlmgr install <pkg>` / `miktex packages install <pkg>` 的具体命令建议（按 `kpsewhich`/ 发行版探测）。

### 3.4 缺分级 / 局部编译（长论文刚需）

学位论文几十章，改一章就全量编译 3\~5 轮很浪费。TeX 原生有 `\includeonly`：



* 新增 `--includeonly=ch1,ch2`（写进命令行 `\includeonly{...}` 或临时 wrapper），跳过未改动章节的排版；

* 配合 C1 的依赖图，可做「只重编受影响章节」；

* 注意：`\includeonly` 会改变 `.aux` 内容，必须与全量构建的 `.aux` 隔离（放到 `Auxiliary/partial/`），否则下次全量编译会误判未收敛。

### 3.5 LaTeXDiff 工作流还差三步



| 问题                                            | 位置                         | 建议                                                                                                   |
| --------------------------------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------- |
| 风格选择用 `input()` 阻塞                            | `cli_latexdiff.py:74`      | 加 `--style 1\|2`，默认读配置；无 TTY 时自动取默认值                                                                 |
| 非法输入不退出（`else` 只 `logger.error`）              | `cli_latexdiff.py:149-156` | 直接 `exit_pytexmk(EXIT_ERROR)`；否则「什么都没编」却返回 0                                                         |
| `-d` 必须两个文件名，且只能比「根目录里有 `\documentclass` 的文件」 | `cli_context.py:189-210`   | 加 `--from-git HEAD~1`（自动 `git show REV:path` 到临时文件）与 `--old-dir/--new-dir`，直接支持「审稿回复」场景              |
| `flatten` 用 `sys.stdout` 重定向                  | `latexdiff.py:114-125`     | 改为 `StringIO`/ 直接写 `handle`；现在一旦 `logger` 走 stdout（RichHandler），日志行会被写进 `.tex` 产物                    |
| `flatten` 的 `\input` 路径按「当前文件目录」解析            | `latexdiff.py:87-101`      | TeX 实际按主文件目录解析；`chapters/ch1.tex` 里写 `\input{sec/a}` 时会找 `chapters/sec/a.tex` 而失败；改为始终相对主文件目录，并加环路检测 |
| `check_aux_files` 要求旧文件也有 aux                 | `latexdiff.py:55-65`       | 旧版本通常没编译过 → 直接拒绝。应允许缺失，仅对 `.bbl/.gls/.idx` 的「带改动标记」模式要求（并自动用新 aux 生成）                                |

### 3.6 引擎参数不可控

目前命令行硬编码：`-shell-escape -file-line-error -halt-on-error -synctex=1` + 交互模式（`compile.py:96-109`）。

建议暴露：



```
[compile]
shell_escape = "auto"        # auto | true | false
interaction = "batchmode"    # batchmode | nonstopmode | errorstopmode
extra_args = ["-synctex=0"]  # 透传给引擎
max_extra_rounds = 10        # 与 MAX_EXTRA_COMPILATIONS 打通
jobname = ""                 # 空 = 用主文件名
```

对应 CLI：`--engine xelatex|pdflatex|lualatex`、`--no-shell-escape`、`--interaction`、`--pass-arg`、`--max-runs`。

### 3.7 文件「往返搬运」是长期风险源

现在是「aux 从 auxdir 搬回根目录 → 编译 → 再把产物 /aux 搬回目录」（`cli_compile.py:115-167`、`compile_engine` 内的 `move_specific_files`）。这带来：



* 编译期间根目录被污染，与编辑器里的 latexmk/TeXstudio 并发时会互相踩 `.aux`；

* `FileMoveRemoveManager._replace` 用 `Path.rename`（`file_ops.py:75`），跨盘符 / OneDrive 占位文件 / 杀毒软件锁定时静默失败（只写 `ERROR` 日志，流程继续）；

* 每次失败都多一轮搬运，失败路径还可能把产物留在根目录（`run_command` 失败分支 `subprocess_runner.py:194-195`）。

建议：



1. 至少把 `rename` 换 `shutil.move`，并对 `PermissionError` 做 3 次退避重试（Windows 上这是最常见的坑）；

2. 中期做「原生命名目录模式」：XeLaTeX `-output-directory=Auxiliary`、`TEXINPUTS`/`TEXMFOUTPUT` 设置、biber `--output-directory`、makeindex `-o Auxiliary/x.nls`，彻底取消搬运（`\includegraphics` 只读，不受影响）；保留现有搬运作为兼容开关。

### 3.8 索引与术语表细节



* `[index]` 段（`index_style_file/input_suffix/output_suffix`）完全未接入（`cli_context.py:149-152`），而 `nomencl` 的样式被硬编码为 `nomencl.ist`（`detection.py:388`）→ 用户自定义 `.ist` 无法使用。建议接通为 `IndexRule` 的可选覆盖，并明确标注「已废弃的 `[index]` 段」或直接删掉该段。

* xindy 语言推断只认 `polyglossia/babel`（`detection.py:227-258`）；`ctex` 文档会退化成 `english`，中文术语表排序错乱。建议增加 `\documentclass[...]{ctex*}` 探测与 `[glossaries] xindy_lang` 覆盖项。

* `makeglossaries` 未使用（直接 `makeindex -s proj.ist`，`detection.py:343`）：对多 glossary、`\glsaddall`、自定义排序规则的文档，`makeglossaries` 更稳（它读 `.aux` 里的 `\@newglossary` 与 `.ist` 语言）。可作为「检测到多 glossary 时优先 `makeglossaries`」的回退策略。

* pythontex / asymptote / `tikzexternalize` 完全没有调度：用到这些的项目会「编译成功但图 / 代码为空」。至少在检测到 `\py{}`、`\begin{asy}`、`\tikzexternalize` 时给出明确提示。

### 3.9 提交 / 归档类功能（对投稿场景价值高）



* `pytexmk package [--arxiv|--elsevier]`：按 `.fls` 收集真实依赖，生成 `submission.zip`（含 `\jobname.bbl`、`figures/`，去掉 `Build/Auxiliary`），这是投稿 / 审稿回复的刚需；

* PDF 摘要：页数、体积、编译轮数、首轮 / 末轮耗时（`Output written on ... (N pages)` 已在 `pytexlogs` 里有正则）；

* 可复现 PDF：子进程环境里加 `SOURCE_DATE_EPOCH=0`、`FORCE_SOURCE_DATE=1`，让同一份源码产出字节一致的 PDF（对 git 跟踪与 latexdiff 都友好）。

### 3.10 多目标与批处理

`-ls` 扫清单、`-s NAME` 编一个，但没有「全编」。建议 `pytexmk build --all`：顺序编译 `[subprojects]` 全部条目，输出一张汇总表（成功 / 失败 / 耗时 / 轮数 / 页数），失败继续下一个（最后统一非零退出）。CI 里跑论文仓库非常有用。

## 4. CLI / 用户体验

### U1 参数语义有陷阱（最高优先级）



1. `-d`**&#x20;吞掉主文件名**：`nargs="*"`（`cli_args.py:110-126`）+ 位置参数 `document`（`:218`）。`pytexmk -d main` 会被解释成「old=main, new=None」，而不是「比较 main」。README 里教用户「把 `-pv` 放到 document 后面」本身就是坏语法的证据。

   建议：`-d/-dc` 改 `nargs=2` 或迁到 `diff` 子命令（`pytexmk diff OLD NEW [--compile]`），旧写法保留但在帮助里标 `[deprecated]`。

2. `-d`**&#x20;省略文件名必报错**：文档承诺「配置了 `[latexdiff]` 就能省略」，但 `_resolve_latexdiff_target` 先判 `len != 2` 直接退出（`cli_context.py:189-198`）。修法：`len==0` 时走配置分支，`len not in (0,2)` 才报错。

3. `-pv`**&#x20;语义过载**：`nargs="?"` + 哨兵字符串 `"preview after compile"`（`cli_state.py:13`）。`pytexmk -pv main` 是「预览 main.pdf」，`pytexmk main -pv` 是「编译后预览」，同一组 token 两种含义。

   建议：拆成布尔 `-pv/--preview` + 子命令 `pytexmk preview [FILE]`，语义唯一。

4. `-ca`**&#x20;/&#x20;**`-Ca`**&#x20;只差大小写**，且 `-c/-C/-ca/-Ca` 四选一（`cli_args.py:133-153`）。建议收敛为 `pytexmk clean [--aux|--all] [--root]`，旧别名保留。

5. `-p/-x/-l` 与 `-v/-vb/-nq` 混排，认知负担高。建议统一 `--engine`、`--verbosity 0..3`。

### U2 帮助与自解释



* `--help`**&#x20;会联网**：`CustomArgumentParser.exit` 里调 `UpdateChecker.check_for_updates()`（`cli_args.py:58-59`）。CI、离线、代理环境都会卡 1 s 上限甚至报错；帮助应该 0 网络。

  建议：把更新检查挪到 `finalize` 唯一一处（现在也是双份），加 `--no-update-check` + `PYTEXXMK_NO_UPDATE=1`，并在 `not sys.stdout.isatty()` 或 `CI=1` 时自动关闭。

* **魔法注释表只出现在&#x20;**`--help`**&#x20;末尾**，`--help` 一屏塞不下；建议独立 `pytexmk help magic`（或 `--help-magic`），并在错误提示里按需引用。

* **退出码未公开**：`lifecycle.py:9-14` 定义了 0/1/3/4/5，但 README 无表；而 `EXIT_CONFIG_ERROR=4` 从未被使用（配置解析失败只是 `logger.error` 后按默认值继续，`config.py:78-80`）→ 用户改错配置时「静默用默认值编译」。

* `-r`**&#x20;只能在浏览器打开**（`cli_early.py:79-82`），SSH / 容器里等于不可用。建议默认用 `rich.Markdown` 在终端渲染（`--open` 才开浏览器）。

### U3 输出层级需要分层

当前每次运行固定打印版本横幅 + 「开始运行 / 开始预处理 / 开始后处理 / 移动结果文件到输出目录…」，`quiet_mode` 只影响 TeX 原始输出（`cli_args.py:154-159`、`cli_context.py:127`）。注意：配置里 `quiet_mode = false` **不生效**—— 代码只在 `if config_dict["quiet_mode"]:` 时把 `non_quiet=False`（`cli_context.py:127-129`），永远关不掉安静模式。

| 档位           | 内容                     |
| ------------ | ---------------------- |
| `-q/--quiet` | 仅失败摘要 + 一行结果（CI 友好）    |

## 5. PyTeXLogs 专项

### L1 `write_report=True` 必崩（P0）

`run_pipeline(..., write_report=True)` 把 `write_report` 作为 **bool 参数**传入 `_run_pipeline_impl`（`engine.py:115, 136`），而该函数内部：



```
if write_report:
    ...
    result_path = write_report(report, actual_path)   # engine.py:412-415
```

`write_report` 在此作用域里是 `bool`；`engine.py` 顶部也没有 `from .report import write_report`（已核对 imports）。因此这条公共 API 分支一执行就是 `TypeError: 'bool' object is not callable`，且 PyTeXMK 目前没传该参数，所以从未被发现。

**实测**（3.13 副本，仅补 `from __future__ import annotations` 以绕过 3.15 注解求值，逻辑未改）：



```
$ python probe.py
--- tool_results (default steps) ---
pdflatex       entries= 1 ...
bibtex         entries= 1 ... warnings_count=2
biber          entries= 0 ...
makeindex      entries= 1 ...
xindy          entries= 0 ...
asymptote      entries= 0 ... figures_processed=1
--- write_report=True ---
TypeError: 'bool' object is not callable
```

字节码层面同样可证：`_run_pipeline_impl` 内 `LOAD_FAST write_report` → `PUSH_NULL` → `LOAD_FAST_CHECK`，即调用局部变量（bool）。

修法：参数改名 `write_report_file`（或函数 import 为 `_write_report`），并补一个测试：临时 auxdir 跑一次 `run_pipeline(write_report=True)`，断言 `report.json` 落盘。

### L2 默认 steps 重复解析同一份日志

`run_pipeline(steps=None)` 固定 10 个 step（`engine.py:102-104`），而注册表里多个 spec 共享同一后缀（`registry.py:108-121`、`157-163`）：



| 场景                 | 被解析两次的文件                                                      | 结果                                                       |
| ------------------ | ------------------------------------------------------------- | -------------------------------------------------------- |
| biber 项目           | `main.blg` 被 `bibtex`（BibtexParser）与 `biber`（BiberParser）各解一次 | 警告重复计数、`by parser` 统计里同时出现 bibtex/biber                  |
| bibtex 项目          | 同上，`.blg` 被 BiberParser 再解一次                                  | 产生不存在的 biber 条目                                          |
| xindy/makeindex    | `main.ilg` 被两者各解一次                                            | 索引警告翻倍                                                   |
| glossaries + xindy | `main.glg` 被 `xindy` 与 `makeglossaries` 各解一次                  | 同上                                                       |
| 任何项目               | `main.log` 命中 `asymptote` 的 `.log` 后缀                         | 多出一个空的 `asymptote` 结果，且 `Output written on` 被当成 asy 输出计数 |

**实测**（同一份夹具同时放了 `main.log`、`main.blg`、`main.ilg`）：`bibtex` 把 `.blg` 解出 1 条警告、`biber` 对**同一份** `.blg` 又解一次（`entries=0`）；`makeindex` 解 `.ilg` 得 1 条错误、`xindy` 对同一份 `.ilg` 再解一次；`asymptote` 把 `main.log` 当 asy 日志解析，得到 `figures_processed=1`。

对 PyTeXMK 的实际影响：biber 项目的 `.blg` 警告会被记在 `bibtex` 名下（`by parser` 统计、`compile_report` 的「参考文献工具」归因都会偏），且 `.blg` 的真实警告可能被 BibtexParser 误解析成 `Warning--` 以外的形态而漏报。

建议：默认 steps 动态化 —— 按 `.bcf` 存在选 biber、否则 `.aux` 里有 `\bibdata` 选 bibtex；按 `.glg/algo` 存在选 makeglossaries 或 xindy；`asymptote` 仅在存在 `*.asy` 或 `\begin{asy}` 时加入；并在 `_run_pipeline_impl` 里加「同一 `log_path` 已被某 step 消费则跳过后续 step」的兜底。

### L3 CLI 输出重复 + 选项被覆盖



1. **摘要打印两次**：`_collect_from_paths` 对目录调 `run_pipeline(...)` 未传 `print_terminal=False`（`cli/main.py:83`），`run_pipeline` 自己就打一遍摘要；随后 `main()` 又 `print_summary(...)`（`:221`），而且在这之前已经把每条 entry 手工 join 进 `lines`（`:211-216`）→ 同一条警告出现 **2\~3 次**。

2. **全局选项被子命令默认值覆盖**：`_build_common_args` 同时挂在顶层 parser 和 `common_parent` 上（`args.py:135-157, 167-169`）。argparse 的行为是「子 parser 默认值覆盖父 parser 已解析的值」，于是 `pytexlogs --severity error check main.log` 实际仍是 `error+warning`；`--format json`、`--output`、`--lang` 同理。

   修法：子 parser 的公共参数用 `default=argparse.SUPPRESS`，或干脆把 `check/summary/export` 变成同一个 parser 的互斥开关（本 CLI 只有 4 个子命令，收益不大）。

3. `"By category: " + join or "(empty)"` 的 `or` 永远不生效（`main.py:208-210`）。

4. 无 `--lang` 本地化默认（固定 `zh`，`args.py:135`），与 PyTeXMK 按 locale 自动选择不一致。

### L4 CLI 能力缺口

| --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `--severity` 只影响 text/open，不影响 `--format json/csv/sarif`（`main.py:192-200`） | 导出前先按 severity 过滤 `results`，或明确写「仅文本」                                                                                                         |

| 无 `--jobname`                                                               | 目录模式靠 `_find_tex_in_dir` 取第一个 `.tex`（`main.py:107-111`），多文件项目会挑到 `appendix.tex`；用「前 16KB 有 `\documentclass`」判定（PyTeXMK 的 `has_magic` 已实现，可复用） |
| `--open` 打开**所有** error                                                     | 默认只开第一条（按文件 + 行号去重），`--open=all` 才全开；避免一次弹 30 个编辑器窗口                                                                                          |

### L5 导出器规范细节



* SARIF：`artifactLocation.uri` 直接用 Windows 反斜杠路径（`sarif_exporter.py:35-56`），不符合 RFC 3986；应转相对 POSIX 并 `quote`。`ruleId` 用 sha1 生成但没在 `tool.driver.rules` 声明，严格校验器会报 unknown rule；补 `rules[]` 与 `partialFingerprints`，GitHub Code Scanning 才能稳定去重。

* CSV：`hint` 列把内部备注表暴露给用户是好事，但 `\n` 未转义（建议用 `csv` 模块的 `QUOTE_ALL`）。

* JSON：`schema_version=1` 与状态文件 `schema_version=3` 语义不同名，建议改成 `report_schema` 以免混淆。

### L6 状态文件锁语义

`_locked` 在**未拿到锁**时仍然 `yield`（`state.py:238-242`），随后 `_mutate` 照常读 - 改 - 写并 `os.replace` → 并发下仍可能覆盖别人刚写的键（锁只防了「同时写」，没防「无锁写」）。既然是「尽力而为」，更安全的做法是：未获锁时直接返回 `False`（放弃本次写），或改用 `filelock` 的真正阻塞语义。当前风险低（单机单人），但 `-pvc`/ 并行批处理上线后会放大。

### L7 两边的集成契约建议

PyTeXMK 调 `run_pipeline` 时（`cli_compile.py:169-175`）目前只传了 `jobname/auxdir/root_file(=项目名)/pytexmk_version/ref_tracker_translate_fn`，且失败路径（`compile.py:87-91`，`root_file=None`）连 `root_file` 都不传。建议补齐：



* `steps=`：由 `LaTeXDetector` 的判定结果生成（biber 就只传 `["pdflatex","biber"]`，有索引就加 `makeindex/xindy`，有 `.asy` 才加 `asymptote`），既修 L2，又让报告语义与「本次真的跑了什么」对齐；

* `print_terminal=False`：摘要由 PyTeXMK 自己渲染（要接 top-N 与 hint，见 U3 / 3.3），避免两边各打一遍；

* `root_file=str(main_file.resolve())`：`--open` 的跳转与相对路径还原才稳定（现在靠 `Path(项目名).parent == "."` 间接指向当前目录，失败路径干脆缺失）；

* `ignore_patterns` / `project_config`：把 `[log] ignore = [...]` 接进配置，用来压掉「draft 模式下的 overfull」这类已知噪声（库已支持，只差上层透传）；

* `language`：`run_pipeline` 目前没有该参数（`print_summary` 有，`printer.py:110`），而 PyTeXMK 用的是 `set_language("log_parser")`——`locale/en/LC_MESSAGES/` 里**没有** `log_parser.po/.mo`，于是英文界面下参考文献变更提示仍是中文（`cli_compile.py:174`）。建议给 `run_pipeline` 加 `language: str | None = None` 并透传给 `print_summary`，PyTeXMK 侧同步补 `log_parser` 的 pot/po。

## 6. 工程与测试



1. **CI 没有真实 TeX**（`.github/workflows/CI.yml`）：只装 Python + `uv sync`，跑 ruff/pytest，然后 `--help` 冒烟。所有「真编译」路径（收敛、aux 搬运、biber / 索引、draft、latexdiff）都没有端到端覆盖。建议加一条 `texlive` job（Ubuntu `texlive-xetex latex-extra bibtex-extra biber` + 一个最小 `\documentclass` 夹具），断言：两轮收敛、`.aux` 归位、失败时退出码 5、draft 后源文件字节不变（这条会直接抓住 C3）。

2. **CLI 参数层零测试**：`-d`/`-pv` 的歧义、`-ca/-Ca` 互斥、子命令默认覆盖（L3）都属「解析器行为」问题，用 `parse_args([...])` 的 table-driven 测试即可防回归，成本极低。

4. **性能**：一次运行会 `rglob("*.tex")` 多次（`_iter_tex_sources` 被 `source_snapshot` 与 `sources_unchanged` 各调一次）、`remove_matched_files` 对每个 pattern 各 `rglob` 一次（`file_ops.py:24-35`，7 个 pattern× 全树）。建议：把 `.tex` 清单算一次缓存进 `WorkflowState`；clean 用一次遍历 + 后缀集合匹配。

* `[index]` 与 `pdf_viewer` 是「配置可写、运行无效」；

* `README` 的 `-d` 省略文件名用法与实现不符（U1）；

* `__init__.py` 注释里的 nuitka 命令与现在 PyInstaller 打包链路不一致。

## 附录 A：三个可直接落地的最小改动

**A1 依赖快照（C1 快修版）**



```
# build_state.py
_DEP_SUFFIXES = {".tex", ".bib", ".bst", ".cls", ".sty", ".def", ".clo", ".cfg",
                 ".ist", ".tikz", ".asy", ".lua", ".svg", ".pdf", ".png",
                 ".jpg", ".jpeg", ".eps"}

def dependency_snapshot(self, root: Path = Path(".")) -> dict[str, dict[str, int]]:
    snap: dict[str, dict[str, int]] = {}
    for p in root.rglob("*"):
        if any(part.startswith(".") for part in p.parts):
            continue
        if p.suffix.lower() not in _DEP_SUFFIXES or not p.is_file():
            continue
        st = p.stat()
        snap[p.as_posix()] = {"size": st.st_size, "mtime_ns": st.st_mtime_ns}
    return snap
```
