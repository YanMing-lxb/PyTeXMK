# PyTeXMK 源码功能分包执行方案

日期为 2026-11-24，基线版本为 PyTeXMK 1.2.18。本方案以当前工作区源码为准，细化[上一版分包建议](2026-11-23-源码功能分包架构建议.md)。

## 1. 范围与基线

沿用现有 `cli/`，依次新增 `runtime/`、`project/`、`build/`。迁移涉及 18 个实现文件，保留文件名、调用签名和运行行为。编译参数归一化、产物发布、缓存策略及索引逻辑的拆分安排在目录迁移验收后。

当前 `src/pytexmk` 下有 49 个 Python 文件，其中 `cli/` 有 12 个，均含 `__init__.py`。Ruff 和 `compileall` 通过，仓库虚拟环境全量 pytest 为 **427 passed**。控制台入口、`python -m pytexmk` 与 `python -m pytexmk.cli` 的版本输出均为 `PyTeXMK 1.2.18`。

工作区缺少 `docs/code-modification-playbook.md`，Git 历史也未查到该文件。`docs/python315-migration.md` 已从工作区删除，分析时从 `HEAD` 查阅。真实 TeX 场景及打包验收列在第 5 节，尚未单独执行。 [仓库约定](../AGENTS.md) · [当前架构与分包门槛](architecture.md)

## 2. 当前执行链及迁移约束

| 阶段 | 实现 | 迁移约束 |
| --- | --- | --- |
| 启动 | 控制台入口和包级 `__main__` 进入 `_launcher`，`cli.__main__` 有独立的版本快速路径 | `-v`、`--version` 在开启惰性导入前返回。保留 `pytexmk:main`、包级惰性导出及三个入口。 |
| 动作分派 | `cli_workflow` 处理早退出、批量、监听、清理、报告、配置解释及编译分支 | 保持现有优先级、退出码和 `-A` 的执行顺序、失败汇总及工作目录恢复。 |
| 项目上下文 | `cli_context` 解析项目根、工作根和主文件，加载配置并应用魔法注释 | 保持按字段计算的覆盖顺序、工作目录语义及 `-ls` 写回行为。 |
| 编译前后处理 | `cli_compile` 负责有效参数、预检、缓存复用、辅助文件准备、归档验证和诊断 | 缓存命中仍输出诊断。保持同目录归档、旧产物识别及 PDF/SyncTeX 配对。 |
| 编译收敛 | `compile_engine.RUN` 驱动 `CompileLaTeX` 与 `CompilationDetector`，由 `BuildState` 持久化 | 保持调度顺序、轮次预算、停止原因和既有状态格式。native Biber 的 `--input-directory` 指向 `auxdir`。 |
| 报告与产物 | `-r` 从现有日志生成 JSON，再以 JSON 生成 Markdown。差异、投稿、PDF、SyncTeX 各有实现 | `-r` 不触发编译，报告路径和退出码保持一致。保留差异流程的辅助文件恢复及投稿范围。 |

## 3. 分包判断与目标目录

根据 AST 统计源码导入。同一来源模块到同一目标模块计一条有向边，纳入函数内导入，排除第三方、测试及动态导入字符串。候选包按仓库现有门槛判断，至少 4 个功能模块、3 条内部边，且外部入边占比达到 70%。占比的分母为外部入边数加包内边数。

| 候选 | 模块 | 包内边 | 外部入边 | 外部入边占比 | 去向 |
| --- | ---: | ---: | ---: | ---: | --- |
| `runtime` | 7 | 8 | 45 | 84.9% | 新建 |
| `project` | 6 | 3 | 13 | 81.3% | 新建 |
| `build` | 5 | 3 | 7 | 70.0% | 新建 |
| `build` 同时纳入 `fls` 和 `layout` | 7 | 7 | 16 | 69.6% | 两个共享模块留根 |
| `artifacts` | 4 | 0 | 4 | 100% | 维持现有文件位置 |
| `reporting` | 3 | 0 | 5 | 100% | 维持现有文件位置 |
| `ui` | 2 | 1 | 23 | 95.8% | 维持现有文件位置 |

```text
src/pytexmk/
├── cli/                       # 已有 CLI，含 cli_report.py
├── runtime/
│   ├── __init__.py
│   ├── file_ops.py            # 文件操作和原子写入
│   ├── subprocess_runner.py   # 进程启动、输出、超时与回收
│   ├── runtime_env.py         # 子进程环境与冻结环境适配
│   ├── paths.py               # 应用及资源路径
│   ├── language.py            # gettext 翻译
│   ├── logger_config.py       # 日志处理器
│   └── timing.py              # 计时和终端宽度
├── project/
│   ├── __init__.py
│   ├── config.py              # 配置读写及合并
│   ├── context.py             # 项目根、工作根和子项目身份
│   ├── tex_project.py         # 主文件和魔法注释
│   ├── subproject_scanner.py  # 子项目扫描及写回
│   ├── preflight.py           # 静态预检
│   └── tex_source.py          # TeX 注释和非代码区域处理
└── build/
    ├── __init__.py
    ├── compile_engine.py      # 多轮执行、收敛和落盘
    ├── compile.py             # 引擎及外部工具调用
    ├── detection.py           # 重跑信号、文献与索引判定
    ├── build_state.py         # 源文件、参数和产物基线
    └── aux_repair.py          # 辅助文件检查和修复
```

根包入口仍为 `__init__.py`、`__main__.py`、`_launcher.py`、`version.py`。`data/`、`locale/` 继续由包根提供。`layout.py` 供清理、扫描、构建、监听及投稿共享，`fls.py` 供构建、PDF 和投稿共享，两个文件留根。`lifecycle.py` 也留根，因为编译、项目解析和差异处理中均有直接退出调用。

产物和报告文件继续位于包根，包括 `submission.py`、`latexdiff.py`、`pdf_tools.py`、`synctex.py`、`diagnostics.py`、`compile_report.py`、`report_export.py`，以及展示模块 `ui_theme.py`、`ui_messages.py`。现有报告链为 `cli_report → diagnostics → report_export`。上一版建议中列出的 `cli_doctor.py`、`cli_completion.py`、`machine_report.py` 已从当前源码删除。

依赖主线为 `cli → build / project / runtime`、`build → project / runtime`、`project → runtime`。共享模块按实际调用保持原有方向。本轮避免让 `project` 或 `build` 依赖 CLI，也避免将报告和编译强行改造成两套不同的接口。 [架构门槛](architecture.md#章节-3新功能放哪的决策树含-5-号规则阈值) · [退出定义](../src/pytexmk/lifecycle.py) · [打包元数据](../pyproject.toml)

## 4. 迁移步骤与每轮检查

| 顺序 | 实施内容 | 通过条件 |
| --- | --- | --- |
| 0. 固定基线 | 记录工作区已有修改和 18 个文件的旧新路径。扫描源码、测试、工具、文档中的旧路径，标注普通、局部和动态导入及补丁目标。核对旧 Python 导入路径有无兼容承诺。 | 当前源码的基线可复现。确有公开承诺的旧路径有明确兼容安排。 |
| 1. 迁移运行基础 | 建立 `runtime/`，移动七个文件并更新引用。将 `language.py` 的源码翻译目录锚定包根，保留冻结版 `_MEIPASS/locale`。核查 `paths.py` 的包根语义。 | 版本入口、帮助、英文翻译和模板读取正常。日志对齐、quiet、超时与进程回收通过。`FileMoveRemoveManager._replace` 的临时文件、`Path.replace` 和失败回滚通过。 |
| 2. 迁移项目解析 | 建立 `project/`，移动六个文件并更新 CLI、编译报告、投稿、差异预处理及 `tests/conftest.py` 的调用。保留 `cli_context` 对 `WorkflowState` 的组装和局部导入。 | 配置合并、魔法注释、主文件和子项目解析、`-ls` 写回、预检通过。额外检查含空格路径及项目根和工作根不同的场景。 |
| 3. 迁移构建核心 | 建立 `build/`，移动五个文件，同步更新 `cli_compile`、`cli_context`、`cli_config` 和 `cli_latexdiff`。保留 `RUN`、`LaTeXDiffRUN` 的签名、调用顺序和状态写入时机。 | 首次编译、缓存复用、依赖变化、轮次预算、辅助文件自愈和 native/传统目录模式通过。核实 native Biber 的实际输入参数。 |
| 4. 完成打包验收 | 更新 `architecture.md` 与开发说明。用独立临时输出目录离线构建 wheel 和 PyInstaller onedir，在脱离源码目录的临时环境安装并验证。 | 新子包进入 wheel，配置与 gettext 资源存在，安装和冻结入口可启动，代表性真实构建通过。遗留的旧路径匹配有明确用途。 |

每轮的最小改动单元包括文件搬迁、对应导入、必要资源定位及测试补丁。子包 `__init__.py` 默认仅保留包说明。内部调用直接导入定义模块。测试里的替身补在被测模块查找符号的位置，例如 `cli_compile` 已直接绑定 `RUN` 时使用 `cli_compile.RUN`。迁移结束后再考虑移动测试文件，保持现有 fixture 作用域。

翻译域和 `.mo` 资源布局沿用原定义。翻译工具已递归扫描 Python 文件并按 `set_language()` 的字面域分组，核对迁移后的收集结果即可。当前冻结打包脚本会清理默认 `build/` 和 `dist/`，因此打包验收使用独立临时目录。回退按本轮文件映射进行，保留已有工作区修改。 [翻译定位](../src/pytexmk/language.py) · [语言工具](../tools/lang_tool.py) · [冻结打包脚本](../tools/pack.py)

## 5. 验收矩阵

每轮先跑关联用例，再执行以下命令。系统 Python 缺少 pytest，使用仓库虚拟环境。

```powershell
ruff check --config pyproject.toml src tests
& .venv/Scripts/python.exe -m compileall -q src/pytexmk
& .venv/Scripts/python.exe -m pytest -q tests
& .venv/Scripts/python.exe -m pytexmk --version
& .venv/Scripts/python.exe -m pytexmk.cli --version
& .venv/Scripts/pytexmk.exe --version
```

最终在隔离项目中对照迁移前后的退出码、外部工具参数、生成路径及状态字段。

| 场景 | 核对内容 |
| --- | --- |
| 启动、帮助、英文界面 | 三个入口的版本一致，轻量版本路径保持，语言资源和默认配置模板可读。 |
| 普通文档首次构建、二次运行、修改依赖后重跑 | 首次编译成功，第二次可复用且仍有诊断，依赖变化会使构建失效。 |
| BibTeX、native Biber、命名索引 | 工具实际调用、Biber 的辅助目录参数及索引轮次与基线一致。 |
| PDF/SyncTeX 归档 | PDF 可读，开启 SyncTeX 时归档配对和跳转有效，同目录场景行为一致。 |
| `-r`、`-c/-C/-ca/-Ca` | `-r` 只读上次日志并产生 JSON/Markdown，缺日志与导出失败的退出码一致。清理范围及产物保留符合每个开关语义。 |
| `-A`、监听、差异稿及投稿包 | 批量执行和失败汇总、监听重新构建、差异辅助文件恢复、归档文件范围一致。 |
| wheel 和冻结包 | 临时环境可安装或启动，包含配置模板和翻译资源，能运行帮助和代表性真实编译。 |

迁移执行遵循当前仓库约定，在本地离线工作，保留系统环境和 MiKTeX 安装，不提交。出现 TeX 工具失败时，先区分测试环境的工具或宏包缺失与代码回归。

## 6. 目录迁移后的独立改进

1. **统一构建参数指纹。** 梳理 `cli_compile._current_build_key` 和 `compile_engine` 用于落盘的参数构造，让复用判定与状态写入共用参数定义。验证旧状态和一项参数变更后的失效行为。
2. **理清产物发布和状态提交。** 先追踪 PDF/SyncTeX 归档及校验后写入产物摘要的路径，再决定如何收拢职责。验收归档失败、旧产物存在及下一次启动的行为。
3. **拆分索引检测职责。** 独立评估从 `detection.py` 提取索引注册、发现及命令生成的边界，沿现有命名索引、术语表、nomencl 和 xindy 测试逐项验证。
