## 二、审计方法

1. **静态扫描**：逐文件 AST 统计用例数、`assert` 数、零断言用例、弱断言类型；
   另扫 `skip/xfail`、同名用例覆盖、测试体内的提前 `return`、`try/except`。
2. **逐文件判定**：读模块说明与全部用例名，对断言强度可疑者回读函数体；
   共 50 个文件，结论见第五节。
3. **定向变异**：临时改写源码一处 → 跑全量 `pytest` → `finally` 按原字节恢复并校验
   sha256。两批共 19 条，覆盖布尔开关、旗标、路径、回滚、去重、指纹。
4. **真实进程探针**：在空目录跑 `python -m pytexmk -dr/-pv/-C/-fr/-sp`，用"退出码 1
   （缺主文件）vs 2（参数错误）"区分"旗标被接受"与"旗标被丢弃"。

## 六、测试流程重组

### 6.1 目录与标记

```
tests/
  conftest.py          # 共享 fixture + 按目录自动打标
  unit/                # 36 个：纯函数/类
  cli/                 #  8 个：解析与分派
  integration/         #  5 个：真实子进程
  regressions/         #  6 个：按轮次归档
  README.md            # 运行方式与写入规范
```

命名统一为 `test_<对象>_<方面>.py`（回归层 `test_<YYYY_MM_DD>_<主题>.py`），
不再出现 `fixes/improvements/deep`；完整索引与“功能变动增删改查”流程见
`docs/测试索引与修改指南.md`。

`pyproject.toml` 新增 `markers = ["unit", "cli", "integration", "regression"]`；
`conftest.py` 的 `pytest_collection_modifyitems` 按父目录名补标记，因此
`--strict-markers` 不会因新文件报错，也不需要逐文件写装饰器。

### 6.2 运行入口

```powershell
python -m pytest -q                    # 全量 552 条
python -m pytest -q -m "unit or cli"   # 快速反馈
python -m pytest -q -m integration     # 端到端（约 10 秒）
python -m pytest -q tests/unit/test_compile.py -k draft
```

### 6.3 共享 fixture

- `repo_root`：仓库根，替代各文件自算 `parents[N]`；
- `run_cli(project, *argv)`：真实子进程 + 自动 `PYTHONPATH=<repo>/src`；
- `make_parser(user_config_dir)`：隔离 `~/.pytexmkrc`。

### 6.4 准入规则（已写入 `tests/README.md`）

1. 断言行为，禁止"只调用不检查"；
2. 新 CLI 开关必须进 `FLAG_CASES` 与帮助页清单；
3. 外部命令用间谍断言完整 argv；
4. 路径用 `repo_root`，子进程用 `run_cli`；
5. 回归用例按日期/轮次归档。

## 七、仍未覆盖 / 后续建议

- **无覆盖率工具**：环境未安装 `coverage`/`pytest-cov`，且本轮约定不联网安装。
  当前用"引用缺口 + 定向变异"替代；后续可在 dev 依赖加 `pytest-cov` 并设
  `--cov-fail-under` 门禁，但不要把行覆盖率当成唯一指标。
- **真实 TeX 链路**：集成用例使用 fake engine/空目录，未在本机跑完整
  `xelatex → biber → makeindex → xelatex`。TeX 缺失是环境限制，不应写成代码回归。
- **平台分支**：POSIX 专属逻辑（xindy/perl、`LD_LIBRARY_PATH` 净化）在 Windows
  上只能测非目标分支；win32 的 `SetDllDirectoryW` 已测，反向"非打包不触碰"已加 spy。
- **变异门禁未自动化**：脚本会改源码，适合人工按季度跑，不适合每次 CI。
