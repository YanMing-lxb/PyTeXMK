# PyTeXMK 返修标记（revmark）集成方案

> 目标：把 `paper-01-dr-ym` 这次手工返修标记的流程，产品化为 PyTeXMK 的确定性能力。
> 基线版本：PyTeXMK 1.2.18；建议以 **1.3.0** 作为特性版本。
> 配套：`2026-11-25-返修标记工作经验与流程.md`
> 本文是设计文档，不含实现代码；文中路径均以当前仓库 `D:\Document YM\Desktop Document\Tools_Development\PyTeXMK` 为准。

---

## 0. 结论摘要

建议新增一组 **revmark 子命令**，围绕三个确定性动作展开：

1. **检查**（`-rv`）：扫描所有 `\input` 到的 `.tex`，按规则报告“标记是否越界、是否嵌套、是否跨段、是否碎片化”；
2. **剥离**（`-rs`）：把 `\chg/\add/\remk` 的包裹去掉，生成一份可投稿的干净源码镜像；
3. **干净构建**（`-rb`）：在镜像里用同一引擎编译，产出 `Build/<main>-clean.pdf`，并与带标记稿比对页数。

配套两个辅助命令：

- `-ri`：幂等插入标准宏块（含“干净模式”外部覆盖开关）；
- `-rd`：对比基线目录与当前稿，生成“哪些段落改了但没标记”的候选报告，**只报告，不自动改源码**。

核心判断：PyTeXMK 不应该做“自动判断 `\chg` 还是 `\add`”的语义工具。语义判断交给作者或上层 LLM；PyTeXMK 负责**结构正确、可关闭、可剥离、可复现**。

优先级建议：

| 阶段 | 内容 | 估算 |
|---|---|---|
| P0 | `-rv` 检查器 + `-rs` 剥离 | 约 4.0 人日（含 M0 规格） |
| P1 | `-rb` 干净构建 + `-ri` 宏块初始化 | 约 2.5 人日 |
| P2 | `-rd` 基线差异辅助 + 发布收尾 | 约 3.0 人日 |

## 1. 定位与边界

### 1.1 工具能做的

- 递归发现主文件通过 `\input` / `\include` 引入的全部 `.tex`；
- 正确跳过注释、`verbatim`、`lstlisting`、`minted`、宏定义体；
- 解析平衡花括号，识别 `\chg{...}` 的真实边界；
- 判断标记是否落入数学环境、浮动体、题注、`\label`、`\cite`；
- 判断是否嵌套、是否跨空行、是否单词级碎片、是否相邻同类未合并；
- 剥离标记，生成干净源码；
- 用同一引擎编译干净稿，检查页数与带标记稿一致；
- 输出机器可读报告，供 CI 或投稿前检查使用。

### 1.2 工具不能做的

- 不能判断“这句话算改写还是新增”——这需要基线语义对比；
- 不能判断“改写后的学术表述是否正确”；
- 不能替作者决定图表、公式、题注里的修改怎么在回复信里描述；
- 不能保证期刊接受彩色标记——这是排版政策问题，不是编译问题。

因此命令命名应避免“auto mark”“smart diff”这类承诺，统一用 `revmark-check / strip / build / init / diff`。

## 3. CLI 设计

### 3.1 新增开关

沿用现有的短开关风格，放进 `meg_revmark` 互斥组：

| 开关 | 长选项 | 行为 | 是否改文件 | 退出码 |
|---|---|---|---|---|
| `-rv` | `--revmark-check` | 只检查，打印问题表与汇总 | 否 | 有 error → 6；否则 0 |
| `-rs` | `--revmark-strip` | 生成干净源码镜像，不编译 | 写 `clean_dir` | 失败 → 7 |
| `-rb` | `--revmark-build` | 检查 → 剥离 → 在镜像中编译干净 PDF | 写 `clean_dir`、`Build/` | 检查失败 6；编译失败 5；剥离失败 7 |
| `-ri` | `--revmark-init` | 向目标主文件导言区插入标准宏块 | 改 `.tex`（幂等） | 冲突/无法写 → 4 或 1 |
| `-rd [BASELINE]` | `--revmark-diff` | 对比基线目录，输出候选差异报告 | 否 | 基线不可读 → 1；否则 0 |

使用示例：

```powershell
# 只检查英文稿
pytexmk main-en -l -rv

# 生成干净源码镜像（不编译）
pytexmk main-en -l -rs

# 生成干净 PDF（需先有带标记稿的 Build/main-en.pdf 用于页数比对）
pytexmk main-en -l -rb

# 初始化宏块（已有则跳过）
pytexmk main-en -l -ri

# 与初稿目录对比，生成“改了但没标”的候选清单
pytexmk main-en -l -rd "C:\Users\lixue\Downloads\初稿"
```

### 3.2 argparse 细节

- `-r` 已经是“从日志生成报告”，不能再占用；`-rv` 是独立的完整选项，argparse 会先做精确匹配，不会拆成 `-r v`。
- `_reject_clustered_short_flags()` 会拦下 `-rvs` 这类合并写法，因为 `-rv` 虽已注册，但 `-rvs` 不是完整选项；这符合现有“短开关不合并”的约束。
- `-rd` 用 `nargs="?"` 且 `const=""`：未出现该开关时 `args.revmark_diff is None`；出现但未给目录时为 `""`，此时回退到 `[revmark] baseline`；两者都为空才报错并提示，绝不静默使用当前目录。
- `-rb` 不自动先编带标记稿。带标记稿仍用普通命令 `pytexmk main-en -l`；`-rb` 只负责干净稿，语义单一。
- 历史注释里提到 `-dc` 曾是“差异稿并编译”，本次**不复用**这个短名：`-dc` 会被 `_reject_clustered_short_flags()` 当成 `-d -c` 的合并写法拦下，而现有代码正是要避免这种“打错一个字换了功能”的风险。
- `-A` 与 revmark 的组合在 P0/P1 不支持：`-A` 的每个子项目需要独立主文件与独立 `[revmark]`，先明确报“暂不支持 -A 与 revmark 同用”，P2 再逐子项目串行处理。

### 3.3 退出码

在 `lifecycle.py` 增加：

```python
EXIT_REVMARK_FAILED = 6          # revmark 检查发现 error
EXIT_REVMARK_STRIP_FAILED = 7    # 剥离/写镜像失败
```

`_EXIT_REASONS` 同步增加两条中文/英文原因。编译失败继续复用 `EXIT_COMPILE_FAILED = 5`，不要为“干净稿编译失败”再造一个码，否则 CI 要区分两套失败语义。

## 4. 配置设计

### 4.1 `[revmark]` 段

```toml
[revmark]
# 总开关：false 时 -rv/-rs/-rb/-ri/-rd 都报“未启用”并退出
enabled = true

# 普通编译前是否顺带检查：off | warn | block
# 默认 off，保证升级 1.3.0 不改变既有构建行为
check_before_build = "off"

# true 时把 warning 也当作 error（CI/投稿前用）
strict = false

# 标记命令名，不带反斜杠；适配用户自定义命名
commands = ["chg", "add", "remk"]

# 报告与干净稿输出
report = "./Build/revmark-report.md"
clean_dir = "./Build/revmark-clean/"
clean_strategy = "mirror"        # mirror | wrapper

# 宏块：inline 直接写入主文件；file 生成独立宏文件并 \input
macro_block = "inline"
macro_file = "revmark_macros.tex"

# 需要检查/剥离的主文件（相对项目根）
targets = ["main-en.tex", "Review/main.tex"]

# \remk 允许出现的目录；正文默认禁止
remk_scope = ["Review/"]

# 基线目录（-rd 未给参数时使用）
baseline = ""

# 粒度与防失控
min_mark_words = 3
max_marks_per_file = 500

# 额外禁止出现在标记体内的命令（项目相关）
forbidden_inner = ["\\gl"]

# 视为保护区的环境名
exclude_envs = [
  "equation", "align", "align*", "gather", "gather*",
  "multline", "multline*", "eqnarray", "eqnarray*",
  "math", "displaymath", "figure", "figure*", "table", "table*",
]

# -rd 的基线文件映射（可选；见 §8.2）
[revmark.diff_map]
# "Section/Section1.tex" = "Section/en/Section1.tex"
```

### 4.2 默认值原则

- `enabled = true`：装了 1.3.0 就能用新命令；
- `check_before_build = "off"`：不装、不用 revmark 的项目，构建路径完全不变；
- `clean_strategy = "mirror"`：稳字优先，wrapper 作为可选加速路径；
- `macro_block = "inline"`：不额外引入文件，投稿打包简单；
- `targets` 默认只列当前项目已知的主文件，**不默认递归扫描整个仓库**，避免把 `docs/`、旧稿、模板中的示例标记也报出来；
- 双语项目（`main-cn.tex` / `main-en.tex`）把两份主文件都列进 `targets`：PyTeXMK 只分别检查/剥离，不自动翻译标记，避免一侧有标记、另一侧没有。

### 4.3 配置读取

在 `cli_context.py` 增加：

```python
def _apply_revmark_config(state: WorkflowState) -> None:
    """[revmark] 段：检查模式、输出目录、目标主文件。"""
    cfg = state.config_dict.get("revmark") or {}
    state.revmark_config = cfg
    state.revmark_enabled = _as_bool(cfg.get("enabled"), True)
    state.revmark_check_mode = str(cfg.get("check_before_build", "off")).lower()
```

`--show-config` 会自动带出新段，不需要额外改 UI。

## 5. 宏块标准与 `-ri`

### 5.1 现有宏块的问题

本次论文的导言区是：

```latex
\newif\ifrevmark
\revmarktrue
\ifrevmark
  \definecolor{colChg}{RGB}{0,80,180}
  ...
  \newcommand{\chg}[1]{\textcolor{colChg}{#1}}
\else
  \newcommand{\chg}[1]{#1}
\fi
```

它满足“开关关闭时原样输出”，但 `\revmarktrue` 是**写死**的。要生成干净稿，只能：

- 物理剥离标记；或
- 改这一行再改回来（容易污染工作区，不可取）；或
- 用外部宏覆盖，但现有块不认外部开关。

### 5.2 推荐标准块

把第二行改成条件判断即可，其余不动。这是对现有工程的最小补丁；`-ri` 新生成的完整块再用 `\providecolor` 替代 `\definecolor`，避免与模板已有同名颜色冲突，属于新建项目的更稳妥写法。

```latex
\newif\ifrevmark
\ifdefined\RevMarkCleanMode
  \revmarkfalse
\else
  \revmarktrue
\fi
```

这样：

- 正常编译：没有 `\RevMarkCleanMode`，`\revmarktrue`；
- 干净构建：wrapper 里 `\def\RevMarkCleanMode{1}`，`\revmarkfalse`；
- 老的 `\revmarktrue` 写法仍能正常编译，只是不能走 wrapper 路径；`-rv` 可以给一条 warning：“检测到硬编码 `\revmarktrue`，干净构建请改用条件块或使用 mirror 策略”。

完整块建议由 `-ri` 写入，并用注释标记边界，便于 `-rs` 精确移除：

```latex
% <revmark:begin> generated by pytexmk -ri; keep this block
\newif\ifrevmark
\ifdefined\RevMarkCleanMode
  \revmarkfalse
\else
  \revmarktrue
\fi
\ifrevmark
  \providecolor{colChg}{RGB}{0,80,180}
  \providecolor{colAdd}{RGB}{0,120,0}
  \providecolor{colRemk}{RGB}{180,0,0}
  \newcommand{\chg}[1]{\textcolor{colChg}{#1}}
  \newcommand{\add}[1]{\textcolor{colAdd}{#1}}
  \newcommand{\remk}[1]{\textcolor{colRemk}{#1}}
\else
  \newcommand{\chg}[1]{#1}
  \newcommand{\add}[1]{#1}
  \newcommand{\remk}[1]{#1}
\fi
% <revmark:end>
```

用 `\providecolor` 而不是 `\definecolor`，避免与模板已有同名颜色冲突；`\newcommand` 保留，若用户已定义 `\chg` 应显式报错，而不是静默覆盖。

### 5.3 `-ri` 的幂等规则

1. 读取目标主文件导言区（`\begin{document}` 之前）；
2. 若存在 `% <revmark:begin>` 块 → 原样保留，打印“已存在，未改动”；
3. 若存在 `\newif\ifrevmark` 但没有边界注释 → 不自动重写（用户可能已定制颜色），只打印补丁建议与行号；
4. 若完全没有 → 在 `\begin{document}` 前插入标准块，保留前后空行；
5. 若 `macro_block = "file"` → 生成 `revmark_macros.tex`，并在导言区插入 `\input{revmark_macros}`，同样带边界注释；
6. 写文件前备份 `.bak`，写入用现有 `atomic_write_text`，避免半截文件。

`-ri` 只改导言区，不碰正文；重复运行不产生第二个块。

### 5.4 回复信单独处理

`Review/main.tex` 使用 `ar2rc.cls`，不加载论文导言区，因此：

- `targets` 默认包含它；
- `-ri` 对它执行同一套插入；
- `-rv` 检查它时，`\remk` 是允许的（`remk_scope = ["Review/"]`）；
- `-rs` 剥离它时，同样把 `\manuscriptfull{\add{...}}` 变成 `\manuscriptfull{...}`。

如果回复信使用独立的颜色名（如 `rc-blue`），标准块的 `\providecolor` 不会覆盖它；视觉上 `\chg` 仍是深蓝，`\add` 仍是绿色。这一点在本次实践中已经验证：引文本身是蓝色，`\add` 绿色最醒目，`\chg` 对比度偏低，属于视觉设计问题，不是宏冲突。

## 6. 检查器设计

### 6.1 数据模型

```python
@dataclass(frozen=True, slots=True)
class Mark:
    path: Path
    start: int          # \chg 的起始反斜杠位置
    end: int            # 配对 } 之后的位置
    body_start: int
    body_end: int
    command: str        # chg / add / remk
    line: int

@dataclass(frozen=True, slots=True)
class Issue:
    path: Path
    line: int
    column: int
    rule: str           # R01..R16
    severity: str       # error | warning | info
    message: str
    hint: str
```

`Mark` 只记录位置，不改文本；剥离时按 `start/end/body_start/body_end` 从后往前替换，保证偏移不失效。

### 6.2 扫描流程

1. **收集文件**：从 `targets` 的主文件出发，递归解析 `\input{...}` / `\include{...}`；跳过 `\input{|...}` 动态路径、`.bib`、图片；遇到 `\input` 目标不存在时报 warning，不中断。
2. **屏蔽非正文**：
   - 注释：未转义的 `%` 到行尾；
   - `\verb|...|` / `\verb*`；
   - `verbatim` / `verbatim*` / `lstlisting` / `minted` / `comment` 环境；
   - 宏定义：`\newcommand`、`\renewcommand`、`\providecommand`、`\def`、`\NewDocumentCommand` 的参数体。
3. **环境栈**：扫描 `\begin{name}` / `\end{name}`，维护栈；`exclude_envs` 内的区间整体标记为保护区。
4. **标记解析**：匹配 `\\(chg|add|remk)\s*{`，用平衡花括号找配对 `}`；找不到即 R02。
5. **规则判定**：对每个 `Mark` 执行 R01–R16；对文件级统计执行 R17–R18。
6. **输出**：按文件、行号排序；同一条问题只报一次。

关键实现约束：

- 不要用正则匹配嵌套花括号；
- 注释屏蔽后要保留字符长度（用空格替换），否则位置偏移；
- `\begin{...}` 的名称可能带 `*`，环境匹配要按完整名称；
- 跨文件 `\input` 的行号按各自文件计算，不混算。

### 6.3 规则表

| 规则 | 严重度 | 触发条件 | 修复建议 |
|---|---|---|---|
| R01 | error | 使用了 `\chg/\add/\remk`，但导言区没有定义 | 运行 `pytexmk -ri` 或手工补宏块 |
| R02 | error | 标记的 `{` 找不到配对 `}` | 检查该行/该段花括号 |
| R03 | error | 标记体内再次出现同类或异类标记 | 拆成并列标记，禁止嵌套 |
| R04 | error | 标记覆盖 `equation/align/...` 或跨其边界 | 把公式留在标记外 |
| R05 | error | 标记位于 `figure/table` 内或跨浮动体边界 | 图表改动写进回复信 |
| R06 | error | 标记位于 `\caption/\label/\cite` 参数内 | 移出参数；句号放在 `\cite` 之后、标记之外 |
| R07 | error | 标记体内出现空行/`\par` | 按段落拆开 |
| R08 | error | 标记体为空或只有空白 | 删除空标记 |
| R09 | warning | 标记体词数（中文按字符）小于 `min_mark_words` | 扩到完整句/段，或改为不标 |
| R10 | warning | 两个同类型标记之间只有空白且非空行 | 合并为一个 |
| R11 | warning | 标记体以标点、空白、`}` 开头或结尾 | 标点移到标记外，清理首尾空白 |
| R12 | warning | 标记体与基线对应段落逐字相同（需 `-rd`） | 说明没有实际修改，删除标记或核实基线 |
| R13 | warning | 基线段落相似度低于阈值但当前稿没有标记（需 `-rd`） | 补标或在回复信说明 |
| R14 | warning | 正文出现 `\remk`，且文件不在 `remk_scope` | 移到回复信，或改 `\chg/\add` |
| R15 | error | 标记体内出现 `forbidden_inner` 命令（如 `\gl`） | 按该命令边界切开，或改用非颜色标记 |
| R16 | error | 标记体内含 `\item/\section/\par/\begin/\end` 等结构命令 | 缩小到纯叙述文本 |
| R17 | info | 一个段落被拆成超过 3 个同类型标记 | 考虑整段合并；确认不是过度碎片化 |
| R18 | warning | 单文件标记数超过 `max_marks_per_file` | 防脚本失控；确认是否整段误包 |

严重度策略：

- `error` 默认阻断 `-rv`（退出 6）；
- `warning` 默认只打印；
- `strict = true` 时 warning 也按 error 处理；
- `info` 永远不阻断，只进报告。

### 6.4 输出

终端用 rich 表格，列：

```
文件:行   规则   级别   摘要   建议
```

末尾汇总：

```
检查 7 个文件，193 处标记：0 error / 3 warning / 1 info
报告已写入 Build/revmark-report.md
```

Markdown 报告按文件分组，附每条的上下文片段（前后各 40 字符），便于直接定位。报告写到 `report` 配置路径；父目录不存在时自动创建。

`-rv` 只读，不写 `.tex`；只写报告文件。若 `report = ""`，则不写文件，只打印。

## 7. 干净稿生成与构建

### 7.1 三种策略对比

| 策略 | 做法 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| A. 就地开关 | 编译前把 `\revmarktrue` 改成 false，编译后改回 | 最快 | 污染工作区；并发/中断会留下错误状态 | **拒绝** |
| B. wrapper 注入 | 生成 `\def\RevMarkCleanMode{1}\input{main}` 的包装文件 | 不复制工程，速度快 | 依赖 `\input` 相对路径与 `\documentclass` 位置；需小样验证 | P1 可选 |
| C. 镜像剥离 | 复制工程到 `Build/revmark-clean/`，物理去掉标记后编译 | 稳；产物可直接投稿；不依赖宏开关 | 复制工程，磁盘与时间成本 | **默认** |

### 7.2 镜像剥离细节

目录结构保持原样：

```
Build/revmark-clean/
  main-en.tex              # 已剥离
  Section/en/Section1.tex  # 已剥离
  ...
  Pictures/                # 硬链接或复制
  References.bib
  .pytexmkrc               # 若存在，复制
```

规则：

- `.tex` 必须**复制后改写**，绝不硬链接（硬链接会改到源文件）；
- 图片、PDF、`.bib`、`.bst`、`.cls`、`.sty` 可以硬链接（同卷），失败则 `shutil.copy2`；
- 忽略 `Build/`、`Auxiliary/`、`.git/`、`Submission/`、`docs/`，避免把产物和文档复制进去；
- 如果 `\input` / `\includegraphics` 指向工程根之外的绝对路径，直接报错并列出文件，不静默生成一个编不过的镜像；
- `Review/` 若在 `targets` 中，按相对路径一并复制并剥离；`-rb` 默认只构建主稿，回复信单独在 `Review/` 里编。

剥离算法：

```python
def strip_text(text: str, marks: list[Mark]) -> str:
    for m in sorted(marks, key=lambda x: x.start, reverse=True):
        text = text[:m.start] + text[m.body_start:m.body_end] + text[m.end:]
    return text
```

剥离后再次扫描，必须得到 0 个标记；否则报 R02/R03 类残留。

### 7.3 宏块清理

`-rs` 默认同时移除 `% <revmark:begin>` … `% <revmark:end>` 块：

- 有边界注释 → 精确删除；
- 没有边界注释但检测到 `\newif\ifrevmark` → 保留块并 warning：“干净稿中仍含 revmark 宏定义，投稿前请手工确认”；
- 正文已无标记时，保留宏块不影响排版，但不适合直接投稿。

### 7.4 编译与校验

`-rb` 流程：

1. 运行检查；有 error → 退出 6，不生成镜像；
2. 生成/更新镜像；
3. 在镜像根目录内用与原稿相同的引擎、相同的 `compiled_program`、相同的 `extra_args` 编译；
4. 产物复制回主工程 `Build/<main>-clean.pdf`，日志复制为 `Build/<main>-clean.log`；
5. 若主工程已有 `Build/<main>.pdf`，用 `pypdf` 比较页数；
6. 页数不一致 → warning（不是 error），提示“检查浮动体/分页是否因剥离而变化”；
7. 清理镜像中的 `Auxiliary/`、`Build/`（可选保留，便于排查）。

缓存：

- 在 `Build/.revmark-cache.json` 记录源文件 SHA256、引擎、参数、镜像路径；
- 源文件未变且 `-fr` 未指定 → 跳过剥离与编译，直接提示“干净稿已是最新”；
- 强制重建直接复用现有 `-fr`，不新增 `--revmark-force`。

为什么页数应一致：`\textcolor` 只改变颜色，不改变字宽、行高、分页；剥离后如果页数变化，通常说明剥离动了文字或宏块，属于必须排查的信号。

### 7.5 wrapper 路径（可选）

```latex
% Auxiliary/_revclean.tex
\def\RevMarkCleanMode{1}
\input{main-en.tex}
```

使用前提：

- 主文件导言区必须是 5.2 的条件块；
- TeX 从项目根目录编译，`\input{main-en.tex}` 能按 cwd 解析；
- `\jobname` 会变成 `_revclean`，必须用 `--jobname main-en-clean` 或 `-jobname` 参数隔离 `.aux`；
- 若主文件用 `\include`，各章 `.aux` 也会按 jobname 隔离。

这条路在 M3（`-rb`）先做一次冒烟测试；不通就只保留 mirror，不要在发布版里承诺 wrapper。

## 8. `-rd` 基线差异辅助

### 8.1 目的

本次手工流程里最耗时的是“找出哪些段落改了”。`-rd` 把这一步变成报告：

- 输入：基线目录（初稿）与当前工程；
- 输出：每个文件的段落对照表，标注 `unchanged / modified / rewritten / added / removed`；
- 再与当前标记求交，标注 `marked / unmarked`；
- **不自动插入任何标记**。

### 8.2 文件映射

初稿的 `Section/Section1.tex` 与返修稿的 `Section/en/Section1.tex` 目录不同，不能按相对路径硬对。策略：

1. 优先用 `[revmark.diff_map]` 显式映射；
2. 没有映射时，按文件名 `SectionN.tex` 在基线中唯一匹配；
3. 仍不唯一 → 报 `unknown`，不猜。

```toml
[revmark.diff_map]
"Section/Section1.tex" = "Section/en/Section1.tex"
"Section/Section2.tex" = "Section/en/Section2.tex"
# ...
```

### 8.3 段落对齐与判定

1. 按空行切段；
2. 去注释、折叠空白；
3. 用 `difflib.SequenceMatcher` 对词级 token 计算相似度；
4. 阈值可配：`unchanged >= 0.97`、`modified >= 0.55`、其余 `rewritten`；
5. 基线有、当前无 → `removed`；
6. 当前有、基线无 → `added`；
7. 当前段落与任一标记区间有重叠 → `marked`。

输出示例：

| 文件 | 当前行 | 基线相似度 | 判定 | 标记状态 | 建议 |
|---|---:|---:|---|---|---|
| Section2 | 56 | 0.42 | rewritten | marked (`\chg`) | 已覆盖 |
| Section2 | 301 | 0.88 | modified | unmarked | 复核是否需要 `\chg` |
| Section4 | 772 | — | added | marked (`\add`) | 已覆盖 |
| Section5 | 40 | 0.99 | unchanged | unmarked | 不需处理 |

### 8.4 与 latexdiff 的关系

- `latexdiff` 是逐词/逐行的通用差异工具，输出 `\DIFadd` / `\DIFdel`，适合“审阅改动”，但对公式、浮动体、复杂宏容易炸，且会把排版微调也算成改动；
- `revmark` 是**作者筛选后的语义标记**，只标“希望审稿人注意的修改”，不是全量 diff；
- `-rd` 借用 latexdiff 的对齐思路，但输出的是“待人工确认的候选段落”，不输出 `\DIF*` 命令，也不自动写源码。

如果用户需要全量逐词 diff，仍建议单独用 latexdiff；PyTeXMK 不把 latexdiff 作为依赖，避免引入 Perl 工具链。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 语义判断被误当成工具能力 | 用户以为 `-rd` 能自动标对 | 文档与帮助页明确写“只报告候选，不自动改源码” |
| `\textcolor` 跨段 | 编译失败 | R07 在编译前拦截；`-rs` 不依赖编译 |
| `\gl` 等用户自定义颜色命令 | 嵌套报错 | `forbidden_inner` 可配置，默认不猜；项目配置里显式列 |
| 不同模板的 `\chg` 已存在 | `\newcommand` 冲突 | `-ri` 先扫描导言区，存在则只提示不覆盖 |
| 镜像漏复制图片/`.bib` | 干净稿编不过 | 复制前解析 `\includegraphics` / `\bibliography`；失败时列出缺失文件，不静默 |
| Windows 硬链接跨卷失败 | 镜像构建中断 | `os.link` 捕获 `OSError` 后回退 `copy2` |
| 页数比较误报 | 用户不信任报告 | 页数差异只报 warning；同时输出两版页数，便于人工判断 |
| `-rb` 与 `-A` 组合歧义 | 子项目串行编译复杂 | P0/P1 明确拒绝组合；P2 再设计 |
| 大型项目复制耗时 | `-rb` 变慢 | 缓存指纹；排除 `Build/`、`Auxiliary/`、`.git/` 等目录，必要时再优化为输入闭包复制 |
| 期刊不接受彩色标记 | 投稿被退 | 干净稿由 `-rs/-rb` 生成，标记稿只用于审稿回复 |
